# Pocket 4Cut 실기기 최종 출시 후보 검증 — 2026-09-22

## 판정과 증거 범위

이번 검증의 기준은 `codex/release-readiness`의 시작 커밋 `1b705cb3cd813efc062eefeed807f595e4b7adf2`와 아래에 적은 **미커밋 앱·테스트 수정이 반영된 작업 트리**다. 최종 커밋과 push 여부는 작업 완료 시 Git 기록으로 확인한다. Android 16/API 36 실물 Samsung 휴대전화 한 대에서 배포 앱 `com.pocket4cut`과 데이터가 분리된 `com.pocket4cut.qa`로 검사했다. 배포 앱을 대체하거나 그 데이터를 초기화하지 않았다. 화면 켜짐 유지 설정은 사용자의 요청대로 변경·검사하지 않았다. 사용자가 이번 검증에서 제외한 글꼴 라이선스와 공개 개인정보 웹페이지도 재검사하지 않았다. 에뮬레이터 추가 검사는 하지 않았다.

**결론:** R8 QA 앱에서 2·4·6컷 핵심 촬영부터 결과 저장·재열기까지 실제 카메라 흐름을 완료했고, 확인된 설정·화면 이동·저장 문제를 수정한 뒤 해당 범위를 재검사했다. 추가 코드 리뷰에서 발견한 선택 이탈·MediaStore 부분 복구·구형 세션 손상 세 경계는 수정 후 빌드와 계측이 통과했다. 보관함에서 복원한 선택 화면의 실제 `홈으로` 경로도 수동 재검사했다. AAB는 생성됐지만 **Google Play 게시 승인이나 모든 기기·입력 조합의 무결함을 판정하지 않는다.** 다른 API/제조사, 낮은 메모리·공간 부족, 실제 공유 수신자 바이트 검사, 접근성 전체 흐름, Play Console의 기존 버전·서명 수용 여부는 이 기기와 로컬 검사만으로 확인할 수 없다. 미실행 항목은 아래에 분리했다.

기존 [에뮬레이터 감사](EMULATOR_AUDIT_2026-09-22.md)는 수정 전 기준 기록이고, [신뢰성 개편 검증](REFACTOR_VERIFICATION_2026-09-22.md)과 [출시 준비 검증](RELEASE_READINESS_2026-09-22.md)은 이전 시점 결과다. 그때의 결과를 이번 실기기 통과 횟수에 합산하지 않았다.

## 사용한 빌드와 데이터 보호

- 실제 기기: Android 16/API 36, 세로 화면의 전·후면 카메라. 이 장치에서 관찰한 결과만 실기기 결과로 기록한다. 기기 식별자와 촬영 이미지·화면 캡처는 이 공개 보고서에 싣지 않는다.
- `qaRelease`는 R8·리소스 축소를 켠 검사 앱으로, 설치 표시 버전은 `1.4-qa-r8 (5)`다. 배포 AAB는 `1.4 (versionCode 5)`이고 이번에 버전 값을 올리지 않았다. `debug` 계측과 `qaRelease`는 같은 QA applicationId를 사용한다. 연결 계측은 QA 패키지를 제거했고 이후 QA APK를 재설치했으므로, 계측 전후 QA 앱 내부 데이터의 연속성을 확인했다고 주장하지 않는다.
- 앱의 사진과 세션을 지우는 `pm clear`, 배포 앱 제거, 사용자 사진 삭제는 실행하지 않았다. 새 QA 촬영·사진첩 사본은 테스트 산출물이다. 기존 사용자 사진의 해시·내용은 수집하지 않았다.
- 촬영 이미지를 PC로 복사해 픽셀·EXIF·원본/결과 JPEG 해시를 대조하는 시도는 개인정보가 담긴 실제 사진 반출에 대한 자동 승인 심사에서 거절됐다. 다른 경로로 우회하지 않았으며 이 검증은 **미실행**으로 남긴다. 로컬 산출물의 AAB 해시와 이 실제 사진 검사는 서로 다른 항목이다.

## 이번 검사에서 수정한 문제

1. **연속 카메라 전환 경합:** 빠른 전·후면 전환이 진행 중인 바인딩과 경쟁할 수 있었다. `CaptureViewModel`에 전환 작업과 기존 바인딩의 직렬화·중복 입력 가드를 연결했다. 최종 QA 앱에서 연속 전환을 눌러 프리뷰가 후면으로 바뀌고 화면이 준비 상태를 유지함을 확인했다. 모든 제조사 카메라 HAL의 실패·복귀를 증명한 것은 아니다.
2. **선택 화면 뒤로가기:** 시스템 뒤로가기와 화면의 닫기 버튼이 다른 경로를 지나 초안을 의도치 않게 떠날 수 있었다. 두 경로를 같은 일시정지 확인창으로 연결했다. 화면 조건별 모든 제스처 뒤로가기 검사는 별도 과제다.
3. **결과 찾기와 사진첩 상태:** 관계없는 손상 세션 하나가 정상 결과 찾기를 막거나, 기록에는 완료로 남았지만 사진첩 사본이 사라진 경우에도 UI가 저장 완료로 표시될 수 있었다. 정상 세션을 독립적으로 찾고 결과 화면 재개 시 MediaStore 행·바이트·pending 상태를 확인하도록 했다. 행 부재가 **확실할 때만** 같은 작업 ID로 재삽입하며 바뀐 행이나 불명확한 상태에서는 중복 사본을 만들지 않고 복구 필요로 남긴다. 새 계측이 손상 세션 격리, 삭제된 행 1회 재생성, 변경된 행 보호를 검사했다.
4. **카운트다운 UI·저장값 불일치:** 슬라이더 조작 직후 설정을 나가거나 다시 열면 표시값과 저장값이 어긋날 수 있었다. UI는 `AppSettings.countdownSeconds`를 직접 표시하고 값 변화 때 저장하도록 바꿨다. 설정값을 같은 값으로 중복 기록하지 않게 했다. 최종 QA에서 1초와 10초를 각각 선택하고 화면 재진입 후 유지되는지 확인했고, Compose 계측으로 1초의 SharedPreferences 기록과 재표시를 검사했다.
5. **설정 닫기 연타 후 빈 화면:** 닫기 동작이 중복 pop되어 홈까지 벗어날 수 있었다. 현재 route가 설정일 때만 pop하도록 가드하고, 두 번 닫기 계측 및 최종 QA의 빠른 닫기 후 홈 화면 유지를 확인했다.
6. **보관함에서 복원한 선택 화면의 이탈:** 확인창의 `홈으로`가 이전 destination으로만 pop해 보관함으로 돌아갈 수 있었고, 저장 완료 전 중복 입력도 가능했다. 선택 저장 중 이탈·선택·다음 조작을 막고, 저장 성공 후 Home route로 이동하도록 보완했다. 실패하면 화면에 머물러 재시도할 수 있다. 내비게이션 계측이 통과했다. 최종 R8 QA에서 2컷 네 장 촬영→두 장 선택→닫기→`홈으로`를 빠르게 두 번 눌러도 Home과 초안 이어하기가 표시됐다. 보관함의 진행 중 작업에서 같은 선택 화면을 다시 연 뒤 `홈으로`를 눌러도 보관함으로 되돌아가지 않고 Home에 도착했다.
7. **MediaStore 부분 pending 행 복구:** 기록 URI 없이 남은 API 29+ pending 행의 바이트가 불완전하면 기존 경로가 복구 필요만 반환할 수 있었다. 같은 작업의 확인된 pending 행을 `INSERTED`로 이어받아 다시 복사하는 경로와 계측을 추가했다. 공개 행·불명확한 소유 행을 덮어쓰는 경로로 확대하지 않았다. 후속 빌드·연결 계측이 통과했다. 실제 provider가 삽입 직후 앱을 종료하는 시점의 검사는 별개다.
8. **구형 단일 세션 파일 손상:** `sessions.json` 가져오기에서 오류가 나면 새 세션별 정상 문서의 보관함 스캔도 중단될 수 있었다. 새 스캔은 구형 오류를 따로 반환하면서 정상 문서를 계속 표시하고 Home/보관함에 경고를 보인다. 구형 파일이 사진 소유 관계를 가질 수 있으므로 파일 삭제·삭제 저널 마무리를 보류하고 원본을 보존한다. 정상 결과 표시·구형 원문 보존·삭제 차단 회귀 계측이 최종 연결 기기에서 통과했다. 손상된 구형 파일의 내용을 복원했다는 뜻은 아니다.
9. **홈의 브랜드 표기:** 사용자 요청에 따라 홈 상단과 홈의 프린트 미리보기 문자열을 모두 정확히 `Pocket 4Cut`으로 맞췄다. 변경 뒤 결합 빌드가 성공했고 최종 QA APK를 실기기에 재설치해 Home UI 트리에서 `Pocket 4Cut` 두 개와 이전 표기 부재를 확인했다. 문자열 변경이며 저장 이미지의 브랜드 렌더나 새 자산 파일 생성은 아니다.

위 9개 묶음은 서로 다른 코드 경계다. 수정 소스는 `CaptureViewModel.kt`, `SelectionScreen.kt`, `SelectionViewModel.kt`, `ResultScreen.kt`, `GalleryExporter.kt`, `SessionDocumentRepository.kt`, `GalleryScreen.kt`, `GalleryViewModel.kt`, `HomeScreen.kt`, `AppSettings.kt`, `SettingsScreen.kt`, `PocketNavHost.kt`, 새 `NavigationGuard.kt`다. 새·확장 계측은 `GalleryExporterInstrumentedTest.kt`, `ResultLinkInstrumentedTest.kt`, `CountdownSettingInstrumentedTest.kt`, `NavigationGuardInstrumentedTest.kt` 및 구형 오류 회귀 테스트다. 기능 아이콘·프레임·스티커·패턴과 Gradle 버전은 변경하지 않았다.

## 실기기 수동 수행과 관찰

**실물 카메라와 권한.** QA 앱 첫 2컷 진입에서 CAMERA 권한을 한 번 거부했고, 앱의 재시도·설정 안내를 거쳐 권한을 허용하자 실제 카메라 프리뷰가 열렸다. 전면과 후면 전환, 줌 확대·축소를 조작했고 프리뷰와 준비 상태가 유지됐다. 방향·미러링은 화면에서 육안 관찰했으나 물리 기준표와 내보낸 JPEG 픽셀의 정량 비교는 하지 않았다.

**중단과 복원.** 2컷의 카운트다운 중 Home으로 이동해 기다린 뒤 돌아오면 자동 촬영을 진행하지 않고 `이어서 촬영`을 표시했다. 앱 프로세스를 실제 종료하고 다시 시작해도 홈에서 `2컷 이어서 작업하기`가 나타났다. 완료된 2컷 경로에서는 총 네 장을 촬영한 다음 선택·편집으로 진행했다. 최종 수정 QA 앱에서 10초 설정 후 약 3초 카운트다운한 상태로 Home에 나가 11초 이상 기다렸고, 복귀 화면은 `0/4`와 `이어서 촬영`이었다. 이 한 타이밍의 결과이며 셔터 콜백 직전·직후, 컷 사이, 잠금·회전의 전 조합은 아니다.

**2컷 끝까지.** 실제 카메라로 4장을 촬영하고 선택 화면에서 네 번째 사진을 첫 번째보다 앞에 놓는 순서를 만들었다. 장미색 커스텀 프레임과 문구, 필름 필터, 사진별 회전·반전·밝기 조절을 적용한 뒤 결과를 열었다. 사진첩 저장을 반복했을 때 새 중복 사본 없이 저장 완료 상태가 유지됐다. Android 공유 시트는 이미지 1개 항목으로 열렸고, 보관함에서 결과를 다시 열었을 때 저장 상태가 유지됐다. 수신 앱의 URI 개방과 JPEG 전 바이트 수신은 확인하지 않았다.

**4컷 끝까지.** 실제 카메라로 8장을 촬영하고 4장을 선택했다. 그리드 배치, 겨울 계절 프레임과 흑백 필터를 적용해 결과를 만들고 사진첩에 저장했다. 계절 장식이 모든 글꼴·화면 크기에서 안전 영역을 지킨다는 전수 증거는 아니다.

**6컷 끝까지.** 실제 카메라로 10장을 촬영하고 6장을 선택했다. 새 비대칭 배치의 첫 사진 큰 슬롯과 다섯 작은 슬롯, 컬러 프레임을 거쳐 결과를 만들고 저장했다. 이 실기기 흐름은 초기 감사에서 빠졌던 실제 6컷 카메라 경로를 보강하지만, 이전 layoutVersion 1을 실제 레거시 사용자 자료로 변환한 검사는 계측 결과와 별개다.

**설정 회귀.** 최종 R8 QA에서 카운트다운 1초를 선택하고 빠르게 나갔다 돌아와도 1초가 표시됐다. 설정 닫기 버튼 연타 뒤에도 홈을 유지했다. 10초 선택도 재진입 후 유지됐고 위 중단 검사에 사용됐다. 화면 켜짐 유지 항목은 손대지 않았다.

**추가 설정·화면 조건.** QA 설정에서 자동 사진첩 저장 ON과 날짜 기본 표시 ON을 선택하고 다시 들어왔을 때 두 값이 유지됐다. 자동 저장을 켠 상태에서 새로 만든 결과 화면은 사용자가 저장 버튼을 누르기 전 `저장 완료`를 표시했다. 이미 만들었던 초안에는 날짜 기본 설정이 소급 적용되지 않았으므로, 이 동작을 날짜 설정 실패로 기록하지 않았다. 검사 뒤 전면 카메라 기본 ON·카운트다운 3초·자동 저장 OFF·날짜 기본 OFF로 돌렸고 화면 켜짐 유지는 손대지 않았다.

시스템 글자 배율은 잠시 0.8에서 2.0으로 바꿔 **홈 화면만** 관찰했고 이어하기·촬영 시작·보관함 버튼이 화면 안에 있었다. 글자 배율을 원래 0.8로 복원했다. 자동 회전과 방향을 잠시 가로 화면으로 바꿔 **홈 화면만** 관찰했을 때 같은 세 버튼이 접근 가능한 위치에 있었고 자동 회전·방향 값을 원래대로 복원했다. 편집·카메라·결과 화면의 2배 글자 또는 가로 전체 흐름을 통과 처리하지 않는다.

수동 검사는 이 한 대의 기기에서 선택한 대표 조합이다. 사용자가 요청한 “모든 경우의 수”를 유한한 기기·시간에서 증명할 수 없으므로, 자동 계약 검사와 미실행 매트릭스를 아래처럼 별도 표기한다.

## 최종 자동 검증과 AAB

홈 브랜드 문자열 변경 뒤 결합 빌드가 성공했고 QA APK를 실기기에 재설치해 Home의 두 표시를 확인했다. 연결 계측 전체도 같은 마지막 소스로 다시 실행했다. opt-in 두 검사는 브랜드 문자열 변경 **전** 별도 실행에서 각각 통과했고, 이후 변경은 Home 문자열 두 개다. AAB 크기·해시는 마지막 문자열 변경을 반영한다.

- 브랜드 변경 전 결합 명령: `./gradlew.bat :app:assembleDebug :app:assembleQaRelease :app:assembleDebugAndroidTest :app:testDebugUnitTest :app:lintDebug :app:lintRelease :app:bundleRelease --offline --console=plain` — **BUILD SUCCESSFUL**, 5분 53초, 172 task 중 42 executed·130 up-to-date. 선택 이탈·부분 pending 행·구형 단일 세션 오류 코드를 모두 반영했다. 브랜드 문자열 변경 뒤 `:app:assembleDebug :app:assembleQaRelease :app:testDebugUnitTest :app:lintDebug :app:lintRelease :app:bundleRelease` 결합 빌드도 **BUILD SUCCESSFUL**, 5분 15초, 144 task 중 35 executed·109 up-to-date였다. `UP-TO-DATE`는 이번에 새로 실행한 작업 수가 아니다.
- JVM 단위 테스트: 결과 XML **1/1 통과**. 이는 기본 산술 테스트이므로 앱 전체 기능 증거는 아니다.
- Debug Lint: **error 0, warning 56, hint 2**. Release Lint: **error 0, warning 41, hint 2**. 두 variant의 검사 범위·경고 개수는 다르다. 기존 경고를 새로 모두 해결했다고 기록하지 않는다.

- 최종 AAB 경로: `app/build/outputs/bundle/release/app-release.aab`. 크기 **38,281,110 bytes**, SHA-256 **`914D9DF8CB66F7E09FF62C9ABFC105D0FA35C810697023EB22FE568A56D2BB48`**. `jarsigner -verify`는 `jar verified`를 반환했다. 자체 서명 인증서 경고가 있었으며 로컬 서명 검사는 Play Console의 기존 업로드 키 일치를 증명하지 않는다. 버전은 계속 `1.4 (5)`다.

## 감사 항목 E01–E10 및 C01–C15의 현재 증거

아래 `실기기`는 이번 한 대의 화면 조작 증거, `계측`은 최종 테스트의 합성/격리 자료 증거, `열림`은 완료 판정에 부족한 범위다. 각 항목의 이전 상세 코드 근거는 위 두 선행 보고서를 참조한다.

- **E01 스티커 렌더:** 계측의 기존 vector 계약은 통과했다. 이번 수동 흐름에서 25종 전부의 저장 JPEG를 육안 검사하지 못했다.
- **E02 문구·날짜:** 2컷 커스텀 문구가 결과까지 이어졌다. 날짜·13개 글꼴·긴 한글/이모지와 모든 배치의 실제 JPEG 비교는 열림.

## 게시 전 남은 확인과 결정 경계

이 기기에서 찾은 처음 다섯 문제는 수정·해당 범위 재검사했다. 추가 코드 리뷰의 세 수정도 빌드·관련 계측을 통과했고, 보관함에서 재개한 선택 화면의 실제 `홈으로` 동작도 수동 확인했다. **로컬 출시 후보 AAB**는 확보했으나 아래 범위는 검사 완료로 기록할 수 없다.

1. API 26/28 사진첩 권한, API 29 전환, 다른 제조사의 카메라 방향·미러링·렌즈 실패. 사용자가 에뮬레이터 추가 시험을 제외했으므로 이번 작업에서 새 에뮬레이터 실행으로 대체하지 않는다.
2. 실제 저장 공간 부족·저메모리·발열, 촬영과 MediaStore의 정확한 중단 시점별 무손실, 모든 글꼴·스티커·색·계절·배치·문구 조합의 픽셀 검수, TalkBack/2배 글자/작은·가로 화면 **전체 흐름**. 홈의 2배 글자·가로 세 버튼만 확인했다. 실물 사진을 PC로 반출한 원본·결과 이미지 메타데이터 확인은 자동 승인 심사에서 거절돼 미실행이다.
3. 기존 단일 `sessions.json` 손상 분리 경로의 합성 계측은 통과했다. 손상된 구형 원문 자체의 자동 복구는 구현하지 않았으며 원본 보존과 명시적 경고가 목표다. 실제 사용자의 구형 파일을 손상시키거나 복구하는 실기기 파괴 검사는 하지 않았다.
4. 실제 공유 수신 앱의 JPEG 바이트 읽기, 클라우드 백업·기기 이전, 이번 변경의 원격 CI 완료 및 Play Console의 기존 `versionCode=5` 수용과 업로드 키 일치. 로컬 AAB가 서명 검사를 통과하더라도 이 외부 상태는 별개다.
5. 글꼴 라이선스와 공개 개인정보 웹페이지는 사용자가 이번 시험에서 명시적으로 제외했다. 제외 항목을 확인 완료로 바꿔 쓰지 않는다.

최종 스토어 게시 버튼을 누르는 결정에는 위 미확인 중 실제 출시 요건을 별도로 확인해야 한다. 사용자 요청에 따라 버전을 올리지 않았으므로 동일 `versionCode=5`가 이미 사용됐는지도 Console에서 확인해야 한다.
