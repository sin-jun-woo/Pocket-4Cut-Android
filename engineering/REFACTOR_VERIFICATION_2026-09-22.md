# Pocket 4Cut 신뢰성 개편 검증 기록 — 2026-09-22

이 문서는 [수정 전 감사](EMULATOR_AUDIT_2026-09-22.md)의 E01–E10·C01–C15를 **변경 코드에 다시 연결한 검증 기록**이다. 시작 기준은 `a0eff04`, 앱 소스·테스트·CI 커밋은 `155ced0b44b381bb8d274d2652d6d2fd421b2973`, 작업 브랜치는 `codex/refactor-reliability`다. 아래의 코드 근거는 2026-09-22 이 코드 커밋 기준이며 문서·증거 파일은 뒤따르는 문서 커밋에 있다. 원래 감사 문서와 그 화면 증거는 수정하지 않았다.

**판정 용어:** `구현+제한 검증`은 코드와 명시한 검사에서 관찰된 범위만 뜻한다. `부분`은 주요 경로를 바꾸었으나 완료 조건 일부가 열려 있다. 이 문서에는 모든 기기·입력 조합의 무결함 또는 출시 준비 완료 판정이 없다.

## 실행 환경과 대표 증거

- Windows, JDK 21, Android SDK 36, Pixel_10_Pro Android 17/API 37 에뮬레이터. 사용 가능한 로컬 AVD와 시스템 이미지는 API 37 계열뿐이다. API 26·28·29·33·36 및 실기기 실행은 별도 환경이 필요하다.
- `debug`는 `com.pocket4cut.qa`이므로 설치된 배포 패키지 `com.pocket4cut`의 사진·설정을 교체하지 않는다. 계측 실행은 QA 패키지의 설치·데이터에는 영향을 줄 수 있다.
- QA의 가상 카메라 합성 장면으로 2컷 4장 촬영 → 프로세스 종료·재시작 → 홈 이어하기 → 두 장 선택 → 필름 블랙 프레임 → 상세 편집 → 완료 JPEG → 사진첩 저장 → 보관함에서 다시 열기를 조작했다. 다시 연 결과의 저장 버튼은 `저장 완료`로 표시됐다. 이것은 MediaStore 행 개수를 독립 쿼리한 증거는 아니다.
- [QA 결과 JPEG](refactor-evidence/2026-09-22/qa-2cut-film-black.jpg)는 1248×3179px, 111,666 bytes의 **에뮬레이터 합성 사진**이다. [재열기 화면](refactor-evidence/2026-09-22/qa-result-reopened.png)은 1280×2856px 캡처다. 사진 내용·색은 실제 카메라 품질 평가용이 아니다. 두 파일은 가상 장면/앱 UI만 담는다.
- 기존 렌더 진단 7개를 기본 androidTest로 편입했고 API 37 선택 실행에서 7/7 통과했다. 특히 이전 실패 4개인 문구 공간, catalog 색 ID, vector 스티커, 새 6컷 기하를 포함한다. 출력 크기/배치 버전 계측 2/2도 선택 실행에서 통과했다. 두 실행은 작은 합성 Bitmap 중심이며 실제 카메라·메모리 압박 검사로 확대하지 않는다.
- 최신 `:app:connectedDebugAndroidTest --offline --console=plain`은 API 37에서 **38/38 통과, 실패·오류·건너뜀 0**이었다. 여기에는 Bitmap 수명, EXIF 8방향, 디코드 한도, 세션 revision/손상/이전/삭제, 결과 게시 journal, MediaStore 중단 재개, 접근성 의미/조작, 6컷 footer 기하가 포함된다. 기기 검사와 결합된 Lint는 API 29 전용 호출의 버전 주석 누락 1개로 실패했으나, 주석 보완 후 debug·R8 QA 빌드/JVM/Lint를 재실행해 **BUILD SUCCESSFUL**을 확인했다. 최종 계측의 38개 테스트 소스는 해당 주석만 추가된 상태에서 변경되지 않았다.
- `:app:assembleDebug`, `:app:testDebugUnitTest`(기본 JVM 1개), `:app:assembleQaRelease`가 성공했다. `:app:lintDebug`는 들여쓰기 오류를 고친 뒤 **오류 0·경고 77·힌트 2**로 성공했다. 최초 결합 검사는 Lint 오류 1개로 실패했으며 수정 뒤 재실행 결과를 최종 기준으로 삼는다. 경고 총수는 수정 전 감사와 같지만 항목별 무증가를 대조했다고 주장하지 않는다.
- R8 적용 `qaRelease` APK를 QA package로 설치·실행해 홈, [권한 안내](refactor-evidence/2026-09-22/qa-r8-permission.png), 권한 허용 뒤 [CameraX 미리보기](refactor-evidence/2026-09-22/qa-r8-camera.png)를 확인했다. [최적화 QA 홈](refactor-evidence/2026-09-22/qa-r8-home.png). 전체 R8 촬영·편집 흐름이나 실제 배포 서명/스토어 검증은 하지 않았다.

## 감사 항목별 코드·검증·남은 조건

### 에뮬레이터 재현 E01–E10

- **E01 스티커 이름 출력 — 구현+제한 검증.** `StickerVectorPainter`와 `CollageRenderer.drawScene`이 preview/export에서 동일한 카탈로그 vector를 그린다. 이름 문자열 렌더 경로를 제거했고 진단 스티커 assertion이 통과했다. 25종 각각의 최종 JPEG 육안 검사는 남았다.
- **E02 문구·날짜 위치 — 구현+제한 검증.** `CollageLayoutMath`와 공유 scene이 프레임 내부의 caption/date 영역을 사용한다. 8배치×문구 조건의 합성 공간 진단은 통과했다. 한글·이모지·최대 길이·글꼴 전체의 시각 검수는 남았다.
- **E03 필름 블랙 색 — 구현+기기 확인.** `FrameColors.byId`가 catalog ID를 해석한다. catalog 색 진단 통과와 API 37의 필름 블랙 선택→편집→JPEG 화면 및 위 결과 파일에서 검정을 확인했다. 전체 45색 조합 검사는 남았다.
- **E04 사진 선택 소실 — 구현+부분 기기 확인.** `selectedPhotoIdsInOrder`를 저장·재구성한다. QA에서 프로세스 강제 종료 후 홈 이어하기로 촬영 사진 4장과 선택 화면을 다시 열고 두 장을 선택했다. 선택 완료 직후 회전·뒤로가기·강제 종료의 모든 타이밍 검사는 남았다.
- **E05 커스텀 프레임 회전 소실 — 부분.** 커스텀 디자인/단계를 세션 초안에 기록하고 복원 인자로 연결했다. 에디터 장식의 TopStart 기준 위치를 최종 정규화 좌표와 맞췄고 단일탭 이동·크기·회전 조작을 추가했다. 다중 제스처 직후 회전·프로세스 종료의 장식별 복원과 텍스트 줄바꿈 일치는 기기에서 재검사하지 않았다.
- **E06 설정 앱 권한 복귀 — 부분.** `CaptureScreen`이 `ON_RESUME`에서 CAMERA 권한을 재확인한다. 시스템 설정에서 거부→허용→복귀를 이번 변경 APK로 다시 조작하지 않았다.
- **E07 사진첩 중복 — 구현+부분 기기 확인.** `GalleryExporter`가 resultId별 작업/URI를 기록하고 자동 저장은 새 결과 route에서만 요청한다. QA의 결과 재열기 UI는 이미 저장됨으로 표시됐다. 동일 결과의 MediaStore 행 수·프로세스 중단 시점별 사본 수는 별도 검사해야 한다.
- **E08 계절 테두리 순서 — 부분.** preview/export가 공유 scene의 배경→사진→테두리→계절 장식→문구→사용자 장식 순서를 따른다. 신규 비대칭 6컷에서는 사진 영역 시작을 조정해 footer 장식과 문구 영역의 기하 간격을 확보하는 계측을 추가했다. 4계절×8배치의 경계·safe area 시각 비교는 남았다.
- **E09 권한 대비·시스템바 — 부분.** 권한 화면은 밝은 배경/읽을 수 있는 텍스트로 바뀌고 밝은 화면에는 어두운 시스템바 아이콘, 촬영 화면에는 밝은 아이콘을 설정한다. QA 홈·편집 화면의 어두운 아이콘을 관찰했다. 최종 APK의 라이트/다크·큰 글자·전체 화면별 대비/TalkBack 검증은 남았다.
- **E10 Home 후 촬영 진행 — 부분.** 촬영 `ON_STOP`은 일시정지를 요청하고 명시적 재개 전 다음 컷을 시작하지 않는 상태 머신을 도입했다. 세션 생성/복원 중에도 `INITIALIZING`에서 일시정지 요청을 기록해 생성 완료 후 카메라가 백그라운드에서 시작되지 않도록 했다. 늦은 CameraX 콜백의 미게시 임시 파일도 정리한다. 이번 QA에서는 2컷 촬영 완료 후 프로세스 복원을 확인했다. 카운트다운·촬영 콜백·컷 간 대기 각 타이밍의 Home/잠금 검사는 남았다.

### 코드·조건부 위험 C01–C15

- **C01 순서 전달 — 부분.** 선택/정렬은 PhotoId 목록, 상세 보정은 PhotoId map, 최종 입력은 `RenderSnapshot` 순서를 따른다. 역순 renderer 진단은 통과했으나 서로 다른 숫자 사진의 화면→최종 결과 E2E는 남았다.
- **C02 원본 재압축 — 구현+제한 검증.** 새 촬영은 pending JPEG의 SOI/EOI·decode bounds를 검사한 뒤 원본 폴더에 게시하며 활성 경로의 `rewriteJpegMaxLongEdge` 호출을 제거했다. 손상 pending은 슬롯을 점유하지 않으며 다시 촬영할 수 있다는 계측 fixture와 원본 bytes 불변 검사가 통과했다. 실기기 EXIF/센서 이미지와 모든 실패 시점의 해시는 남았다.
- **C03 세션 JSON 손상 — 구현+제한 검증.** 세션별 schema/revision, 프로세스 Mutex, `AtomicFile`, last-good/복구 필요 상태를 도입했다. 결과 파일 게시 전 별도 AtomicFile 저널을 기록하고 파일 게시 후 문서 갱신 전 종료되면 다음 조회에서 결과를 1회 등록한다. 새 결과 JPEG가 손상된 journal은 기존 정상 결과를 읽을 수 있게 두고 해당 초안을 `NEEDS_RECOVERY`로 표시하며 편집과 새 결과 준비를 차단한다. stale revision·손상 주 파일·이전 중복·결과 저널 계측 검사를 실행한다. journal 자체의 사용자 복구 조작, 촬영/삭제의 전 단계 장애·공간 부족 주입과 다중 프로세스 접근은 남았다.
- **C04 삭제 소유권 — 부분.** tombstone과 앱 소유 경로 검증을 사용하고 다른 세션이 참조한 사진을 보존하는 계측 검사가 있다. 해당 세션의 미완료 결과 저널과 `<id>.corrupt.<timestamp>` 원문 정리를 추가했다. 중단된 삭제의 모든 단계와 사용자 기존 데이터 삭제 확인은 남았다. 사진첩 공용 사본은 세션 삭제 대상이 아니다.
- **C05 API 26–28 저장 권한 — 코드 구현·OS 미검증.** `WRITE_EXTERNAL_STORAGE`를 28 이하에만 선언하고 `ResultScreen`이 필요한 시점에 권한을 요청한다. 로컬에 구형 시스템 이미지가 없어 API 26/28 거부·허용·재시도는 실행하지 못했다.
- **C06 취소·메모리 — 부분.** 오래된 preview 게시를 취소/버전 검사하고 원본 디코드·최종 렌더에서 비트맵 소유권을 명시했다. 일반 편집 필터는 사진별 복제 Bitmap을 만드는 대신 공통 Canvas가 원본을 선택 필터로 그린다. `BitmapPipelineInstrumentedTest`와 Bitmap 수명 검사가 EXIF·샘플링·preview 경쟁·필터 전환을 다룬다. 256MiB 메모리 클래스와 실제 16MP 최대 장면에서 128MiB 렌더러 예산은 측정하지 않았다.
- **C07 회전·배율 — 구현+제한 검증.** 저장 회전은 라디안, 제스처 경계는 도→라디안 변환이다. 스티커/계절 장식은 preview/export 공통 Canvas 경로를 쓴다. 장식별 다중 손가락 제스처의 정량 픽셀 비교는 남았다.
- **C08 6컷 중복 배치 — 구현+진단 통과.** 신규 `SIX_COLLAGE` version 2는 첫 사진 2×2, 나머지 5개의 비대칭 슬롯이다. 버전 없는 이전 초안은 version 1의 3×2를 유지한다. 진단의 중복 기하 assertion이 통과했다. 실제 6컷 촬영→편집→결과 기기 검사는 남았다.
- **C09 오류/취소 — 부분.** 촬영 콜백은 취소 가능한 coroutine이며 늦게 도착한 완료·실패 콜백은 해당 미게시 임시 파일을 정리한다. 저장·보관함은 실패 상태를 화면에 전달한다. 실제 CameraX 연결 실패·저장 공간 부족·JSON 손상 UI의 재시도/복구는 기기에서 전부 검증하지 않았다.
- **C10 프로세스 복원 — 부분.** 세션 문서와 SavedStateHandle의 세션 ID로 촬영/선택/일반·상세 편집을 복원한다. QA에서 촬영 완료 세션의 프로세스 종료→홈 이어하기를 관찰했다. 입력 debounce 직후 강제 종료, 상세 보정·커스텀 프레임 전 단계는 남았다.
- **C11 백업 범위 — 코드 구현·복원 미검증.** 구형 `backup_rules`와 Android 12+ `data_extraction_rules`는 설정 두 파일만 허용하고 사진·문서·내보내기 기록을 제외한다. 패키지된 Manifest/XML 허용 목록 계측 2/2는 API 37에서 통과했다. 실제 cloud/device transfer 복원은 실행하지 않았다.
- **C12 설정·접근성·CI — 부분.** 카운트다운 기본 3초·범위 1–10초, QA applicationId, Android CI 빌드/검사 정의를 정리했다. 선택 순서·날짜 스위치·슬라이더 값, 사진 순서 이동 동작, 장식의 이동·크기·회전 버튼과 48dp 영역을 계측 5개로 검사했다. 실제 TalkBack 완주, 2배 글자/가로 화면 전 화면 조작과 원격 CI 결과는 남았다.
- **C13 후속 색/그라데이션 — 부분.** 선택 color ID와 gradient stop을 공통 preview/export 입력에 연결했다. 커스텀 디자인 이후 모든 색 선택·45색 round trip의 화면 결과 검사는 남았다.
- **C14 MediaStore 부분 실패 — 부분.** exporter는 작업 상태, `IS_PENDING`, 게시 결과 검사, 자기 작업 항목 정리와 복구 필요 상태를 가진다. 기록 URI를 표시 이름·소유자·경로와 다시 대조하고 완료 항목의 JPEG byte hash도 확인한다. API 29 이상은 pending 행까지 조회해 PREPARED 중단 시 기존 행을 재사용하거나 행 부재가 확인되면 같은 작업으로 삽입을 재개한다. API 37의 pending/URI 혼동·행 부재 재개 fixture는 통과했다. insert 직후·복사 중·게시 직후 실제 강제 종료 및 API 26–29 provider 실패 주입은 남았다.
- **C15 계절 장식 좌표 — 부분.** scene 공통 배율과 그리기 순서를 적용했다. 신규 6컷 사진/계절 footer/문구 간격은 기하 계측으로 확인했다. 8배치×4계절 safe area assertion과 대표 JPEG 육안 검수는 아직 없다.

## 남은 통합·출시 검증

현재 검증은 **정의된 전체 계획의 완료 증거가 아니다.** 다음은 독립 완료 조건으로 남긴다.

1. API 26/28/29/33/36 기기와 API 37에서 권한·MediaStore·백업/복원·프로세스 중단 매트릭스 실행.
2. 실제 전·후면 카메라, 센서 방향/미러링, 연속 촬영·잠금·발열, 공유 수신 앱의 JPEG byte 읽기.
3. 선택·커스텀·상세 편집의 회전과 실제 프로세스 종료, 손상·누락·미래 스키마·저장 공간 부족·메모리 부족의 단계별 실패 주입.
4. 8배치×4필터×문구 조건, 4계절·45색·25스티커·글꼴, EXIF 8종, 다양한 비율·2배 글자·TalkBack의 자동 assertion과 대표 출력 육안 검수.
5. 미리보기 프록시의 영속 캐시, NavHost의 남은 I/O, 일부 지연 저장/시스템 뒤로 flush, 촬영·삭제의 중단 journal 및 누락/손상 JPEG 복구 경로를 완료하고 테스트로 증명. 결과 게시의 선기록/재생은 구현됐지만 JPEG 생성 전 중단된 빈 저널의 정리 정책은 남아 있다.
6. 원격 CI, R8 QA의 전체 흐름, Lint 경고 77개 각각의 처리/기준 대비 차이, 실기기 결과를 별도 기록. 미실행은 통과로 적지 않는다.

### 후속 작업의 우선순위와 종료 조건

1. **데이터 손실 경계:** 촬영 파일·세션 문서, 삭제 tombstone·파일, 결과 journal·완료본, MediaStore insert·복사·게시의 각 경계에서 프로세스를 실제 종료하거나 저장 오류를 주입한다. 재시작 뒤 기존 사진/JPEG 해시, 세션 수, MediaStore 행 수를 비교한다. 현재 손상 결과 journal은 표시/편집 차단까지만 갖고 있어 사용자가 안전하게 격리·복구할 수 있는 조작이 필요하다.
2. **촬영과 화면 수명:** 1/3/10초 카운트다운의 시작·중간·셔터 요청·컷 간 대기마다 Home·잠금·회전·권한 회수를 반복한다. 완료 수는 게시된 사진과 세션 기록이 일치해야 증가하고, 명시적 재개 없이 새 셔터가 실행되면 실패다. 최근 `INITIALIZING` 수정은 이 전체 타이밍 매트릭스를 대체하지 않는다.
3. **렌더 동등성:** 번호·색·방향이 분명한 합성 사진으로 8배치×4필터×문구/날짜 4조건을 비교하고, 45색·25스티커·4계절·현재 글꼴 목록을 저장/재열기/재렌더한다. 비대칭 6컷과 커스텀 장식 텍스트 줄바꿈은 대표 JPEG 육안 검사도 필요하다. 서로 다른 화면 크기에서 동일 draft revision의 출력 치수가 같아야 한다.
4. **메모리·접근성·OS:** 최대 16MP 출력에서 256MiB 메모리 클래스의 앱 전체 peak와 renderer 소유 Bitmap을 분리 측정하고, 더 낮은 한도에서는 초안/완료본을 보존한 오류로 종료해야 한다. TalkBack, 2배 글자, 가로/작은 화면, API 26/28/29/33/36, 실제 Android 백업/복원과 물리 전·후면 카메라를 각각 기록한다.

위 네 묶음은 추가 제안이 아니라 원 계획의 아직 통과하지 않은 완료 조건이다. 따라서 이 브랜치의 현재 판정은 **핵심 경로 구현과 API 37 제한 검증 완료, 전체 계획과 출시 검증은 미완료**다.
