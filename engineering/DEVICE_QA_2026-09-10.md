## 우선 조치

1. **P1: 화면에 공개한 Bitmap의 조기 recycle**. 실제 과거 충돌 메시지와 일치하는 수명 결함을 기기 진단 테스트로 확인했다. UI가 참조하는 이미지 소유권과 해제 시점을 먼저 고쳐야 한다.
2. **P1: 촬영 중 백그라운드 전환 시 실패와 부분 촬영 복구 부재**. 카메라가 멈춘 뒤 촬영 루프가 계속 실행된다.
3. **P1: 사진 재정렬 인계 누락·편집 초안 복원 부재**. 출력의 사진 순서와 작업 보존이 보장되지 않는다.
4. **P2: 미리보기와 저장 결과 불일치**. 문구/날짜 영역, 프레임색, 스티커의 모양·위치·크기가 서로 다르다.
5. **P2: 저장/삭제/권한 복귀**. 중복 자동 저장, 취소·삭제 후 잔존 자료, 권한을 이미 허용했어도 남는 안내 화면을 수정해야 한다.

- `:app:assembleDebug`: 성공. APK를 기존 앱 위에 데이터 유지 방식으로 설치하고 실행했다. 최초 APK 패키징이 수행됐으며, 최종 결합 검사에서는 UP-TO-DATE였다.
- `:app:testDebugUnitTest --rerun`: 실제 재실행 성공, 기본 산술 테스트 1개. 이 성공은 앱 기능 검증을 뜻하지 않는다.
- 기본 Android 계측 테스트 `ExampleInstrumentedTest`: 실기기 1개 통과. 패키지명 확인이다.
- `:app:lintDebug`: **실패 — Error 1, Warning 91, Hint 2**. 차단 오류는 `AndroidManifest.xml:6`의 `PermissionImpliesUnsupportedChromeOsHardware`. 기존 오류를 suppress하지 않았다.
- 별도 진단 APK 빌드: 성공. Kotlin daemon 첫 시작 메시지가 있었으나 최종 빌드 종료 결과는 성공이었다.
- **추가 계측 테스트: 7개 실행, 2개 통과, 5개 실패**. 실패는 알려진 잘못된 동작을 통과 처리한 것이 아니라 기대 계약에 대한 assertion 실패다.

## 결함 상세

이하 소스 경로는 `app/src/main/java/com/pocket4cut/` 기준이다. P1은 핵심 흐름·작업 보존 문제, P2는 기능·신뢰성·접근성 문제, P3는 보조 UX/제품 표기 문제다.

### QA-01 · P1 · 해제한 Bitmap을 Compose가 그리는 튕김

- 증거: 기기에 남은 2026-09-10 13:26 충돌은 `Canvas: trying to use a recycled bitmap`. `BaseCanvas.throwIfCannotDraw:84 → RecordingCanvas:265 → BitmapPainter.onDraw:89` 경로다.
- 첨부 1의 스택은 이 경로와 일치한다. 첨부 2도 같은 draw 경로이며 Android framework 후반 줄 번호가 다르다. 첨부에는 상세 예외 메시지·버전·발생 조작이 없으므로 **서로 다른 두 버그로 중복 집계하거나 정확한 버튼을 스택만으로 단정하지 않는다**.
- `presentation/detailEdit/DetailEditViewModel.kt:272,296`은 UI에 이미 전달한 preview Bitmap을 새 상태 게시 전에 recycle한다. 기기 진단에서 이전 상태 참조가 실제 recycled 됨을 확인했다.
- 회전/반전/보정/초기화 및 ViewModel 제거 시 해제 경로(`DetailEditViewModel:379`, `EditViewModel:278`)가 관련 후보다. `CollagePreview.kt:505` 등의 Compose 소비자는 `asImageBitmap()` 참조를 사용한다.
- **한계:** 이번 수동 연속 편집 조작에서 새로운 FATAL은 재현되지 않았다. 진단은 수명 위반을 재현했으며 Compose의 실제 프레임 경합 시점을 재현했다고 말하지 않는다. 과거 기기 충돌은 확인된 사실이다.
- 증거 색인: `preexisting-crash.txt`, `diagnostic-results.txt`, `19-after-rotation`, `20-adjustment-stress`.
