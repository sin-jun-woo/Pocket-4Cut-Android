## 선택 화면

- 상위 탭은 **기본 / 기념일 / 직접 기록**으로 나눕니다. 기본에는 기존 색상·시즌 4종과 커스텀 편집 진입을 보존하고, 기념일에는 77종, 직접 기록에는 특수 11종을 둡니다. 기존 봄·여름·가을·겨울을 새 기념일로 교체하지 않습니다.
- 카탈로그의 **기념일·러브·프렌즈·홀리데이·트래블·라이프·이벤트·패밀리·메모리·커스텀** 10분류에 기존 **시즌**을 별도로 유지합니다. 각 탭에는 실제 항목이 있는 분류만 보여 빈 카테고리를 만들지 않습니다. 한 테마의 주 분류는 하나로 유지하고, 졸업·여행처럼 여러 맥락에 걸치는 항목은 검색 태그로 연결합니다.
- 검색은 이름·기념일 별칭·태그를 대상으로 하며 `100일`, `첫돌`, `퇴사`처럼 사용자가 떠올리는 단어를 지원하는 방향입니다. **전체 / 즐겨찾기 / 최근 선택**은 카테고리와 독립된 필터입니다. 필터 조합으로 결과가 없으면 조건 초기화를 제공합니다.
- 카드에는 대표 그림·이름·선택 상태를 표시하고, 탭하면 현재 사진과 현재 2·4·6컷 배치로 큰 미리보기를 보여 줍니다. 확인 버튼으로 적용한 뒤에만 최근 선택에 추가합니다. 탭·검색·스크롤은 화면 복귀 시 유지하고, 모든 버튼은 48dp 이상 조작 영역과 접근성 이름을 갖게 합니다.

## 실제 연결 지점과 데이터

- 현재 [`PocketNavHost.kt`](../../../../app/src/main/java/com/pocket4cut/presentation/navigation/PocketNavHost.kt)의 프레임 destination 안에서 `frameStep`으로 `choose/color/season/custom`을 전환합니다. 별도 최상위 흐름을 새로 만들기보다 이 경계 안에 기념일·직접 기록 선택을 추가하는 것이 작은 변경입니다. 현재 이 화면을 연결하는 것은 `FrameFlowCoordinatorScreen`이며, 이름이 비슷한 `FrameThemeSelectScreen`을 활성 진입점으로 오인하지 않습니다.
- [`SessionDraft`](../../../../app/src/main/java/com/pocket4cut/domain/model/SessionDocument.kt)의 `customDesignJson`은 `PendingCollageStore` 직렬화 → `EditViewModel` → 상세 편집 → `RenderSnapshot`으로 전달됩니다. 기존 `themeId`, `layoutId`, `layoutVersion`, `sourceSeason`은 유지합니다. 기념일에는 별도의 안정적인 `occasionId`, 디자인 버전, 입력값을 추가하는 방안을 설계하고 `sourceSeason`을 기념일 ID로 재사용하지 않습니다. 새 필드의 기본값·이전 JSON 읽기·알 수 없는 ID의 안내 동작을 함께 정해야 합니다.
- 선택 결과는 기존 `SessionDocumentRepository.update`의 revision·Mutex·원자적 저장 경로로 기록합니다. 직접 JSON 파일을 덮어쓰지 않습니다. 카탈로그 수정이 이미 저장한 결과 JPEG를 바꾸거나, 초안의 날짜·문구를 다시 계산해 바꾸지 않도록 렌더 시점의 확정값을 보존합니다.
- 즐겨찾기·최근 선택에는 테마 ID만 저장하는 별도 SharedPreferences가 적합합니다. 최근 목록은 중복 제거·개수 제한을 두고, 개인 문구·장소·사진 경로는 넣지 않습니다. 현재 백업 허용 목록은 `pocket4cut_settings.xml`과 `pocket4cut_theme.xml`뿐이므로 새 선호도 파일의 백업 여부는 별도 결정 사항입니다.

## 직접 기록 11종과 동적 글자

**우리의 첫 네컷 / 오늘의 네컷 / 이번 달의 네컷 / 올해의 네컷 / 여기서 한 컷 / 오늘의 날씨 / 지금 이 순간 / D-Day / N번째 네컷 / 한 줄 기록 / 커스텀 기념일**은 현재 모두 디자인 자료입니다. 날짜·시간 자동 삽입, D-Day 계산, 위치·날씨 조회, N번째 기록 집계는 구현되어 있지 않습니다. 이미지 속 `2026`, 날짜, 장소, 온도, 횟수는 예시이며 실제 자동 결과로 소개하지 않습니다.

후속 구현에서는 제목·날짜·이름·문구를 이미지에 굽지 않고 정확한 글꼴로 별도 텍스트 영역에 배치합니다. 기존 일반 편집의 사용자 캡션과 충돌하지 않게 전용 필드와 안전 여백을 정의해야 합니다. 시간대·표시 형식, D-Day 시작일의 0일/1일 기준, N번째 집계 범위는 명시적으로 정하고 사용자가 수정할 수 있게 합니다. 장소·날씨는 우선 직접 입력을 제공할 수 있으며, 자동 조회는 서비스·권한·네트워크 실패·개인정보 처리를 설계한 뒤 별도로 구현합니다. 긴 이름·한글·큰 글자에서도 사진 칸을 가리지 않도록 줄 수·크기·입력 길이 정책이 필요합니다.
